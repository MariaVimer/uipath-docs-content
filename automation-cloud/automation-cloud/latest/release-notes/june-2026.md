## June 26, 2026

### Agent Evaluations: Prompt Coverage

Prompt coverage lets you control the breadth of evaluation use cases for your agent before deployment. Avoid publishing agents with low coverage since uncovered use cases increase the risk of failures in production.

The prompt editor displays a Prompt Coverage indicator that calculates how much of your prompt is tested by evaluations. For each use case defined in your prompt, it checks whether a corresponding evaluation exists and shows an overall coverage percentage. Use this to track progress as you build out your eval suite and identify gaps that still need coverage.

## June 25, 2026

### Process-scoped roles for Case Management solution deployments

When a Case Management solution is deployed, the custom roles (personas) defined in the solution are scoped to specific processes and stages rather than to the tenant. These roles do not appear in the tenant-level **Manage Access** interface and are managed through the solution deployment and upgrade lifecycle.

### Bug fixes

- Resolved an issue with adapter identifier validation for organizations using SCIM provisioning or SAML authentication with Microsoft Entra ID.
- Resolved a security issue where display name content in user invitation emails was not properly handled.

## June 24, 2026

### Bring your own model for Semantic activities

You can now power UI Automation **Semantic activities** with your own large language model subscription instead of the UiPath-managed subscription, using one of the supported models.

You can now set project-level defaults for Semantic activities — the default model for each activity and the extraction mode for **Extract UI Data (Preview)** — under **Project Settings > UI Automation Modern > Semantic Activities**. These defaults apply both during Studio design-time experiences, such as selection and test runs, and at runtime.

For more information, refer to:

* [Configuring LLMs](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/configuring-llms#configuring-llms-for-your-product) for the list of supported models.
* [Semantic activities bring-your-own-model setup](https://docs.uipath.com/activities/other/latest/ui-automation/ui-automation-semantic-activities#bring-your-own-model-setup) for the setup steps.
* [UI Automation Modern Project Settings](https://docs.uipath.com/activities/other/latest/ui-automation/project-settings-ui-automation-next#semantic-activities) for the project-level defaults.

### New default model for Semantic activities

Updating the UI Automation Activities package changes the default model for Semantic activities (excluding Close Popup) to PathMini.

## June 18, 2026

### Azure Private Link Support for Automation Cloud

Organizations with strict network security requirements can now connect to Automation Cloud without routing traffic over the public internet. By using Azure Private Link you can establish a private, secure connection between your Azure environment and UiPath Automation Cloud. This means your automation workloads — including Robots and Task Mining devices — connect to UiPath services over a private network path rather than the public internet, reducing exposure to external threats and helping you meet regulatory and compliance requirements.

#### Why it matters

- **Stronger security posture** — traffic between your environment and Automation Cloud travels over a private network path instead of the public internet, minimizing the attack surface.
- **Compliance-ready** — supports organizations operating under strict data residency or network isolation policies.
- **Business continuity built in** — primary (West Europe) and secondary (North Europe) gateways keep your automations connected even during a regional outage.

For more information on Azure Private Link with Automation Cloud, refer to Connecting to [UiPath using private link](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/connecting-to-uipath-using-private-link).

### SCIM User Sync for automated directory user management

System for Cross-domain Identity Management (SCIM) User Sync is now available in **public preview**. Built on the SCIM standard, SCIM User Sync eliminates manual user management by synchronizing user creation, updates, and deprovisioning events directly from your corporate directory.

## June 16, 2026

### Relay client 26.4.2 simplifies network requirements

Relay client version `26.4.2` supports connecting the persistent tunnel through the standard Automation Cloud URL, `cloud.uipath.com:443`. This means new `26.4.2` configurations no longer need connectivity to a region-specific relay hostname, such as `eu-relay.uipath.com`, for the tunnel.

Relay client versions earlier than `26.4.2` continue to work with regional relay hostnames. Keep those hostnames allowlisted until you move to Relay client `26.4.2` or later and connect through `cloud.uipath.com`.

<!-- TEMP-RELAY-ROLLOUT: remove this gradual-rollout note once the cloud.uipath.com connection path is generally available in all regions (~2026-07-09). Keep the version-based wording. -->
Availability follows the Automation Cloud regional rollout: the new connection path is being made available gradually in each region. Until it reaches your region, continue using your current Relay client configuration.

For details, see [Deploying the Relay client](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/deploying-relay-client).

### Relay client command and operations improvements

Relay client version `26.4.2` adds the `relay describe <id>` command for inspecting a Relay client's status, service settings, configured paths, and local metadata. The `relay list` command now shows the relay group name when available, and JSON output includes the full group name.

This release also adds operational controls for log management on installed services. You can set rotated log retention with `--log-retention-days` during `relay start` or `relay restart`, and you can relocate the log directory for an installed service by running `relay restart <id> --logs-dir <path>`. For container deployments, the Relay client exposes the `/healthz` endpoint on `0.0.0.0:9090` by default, with `--health-addr` available to change or disable the bind address.

## June 10, 2026

### New License Viewer and License Administrator roles

Two new roles - **License Viewer** and **License Administrator** - are now available for Automation Cloud organizations. These roles let Org Admins delegate license management without granting full Org Admin access.

The **License Viewer** role provides read-only access to all Licensing pages in the Admin Console. The **License Administrator** role provides full access to all licensing actions, equivalent to the licensing capabilities of an Org Admin. Both roles are assignable at the organization level.

For more information, see [Licensing roles](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/about-licensing-roles) and [Licensing role permissions](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/licensing-role-permissions).

## June 8, 2026

### PII masking extended to files [Preview]

PII in-flight masking now covers files that are dynamically downloaded by agents during runtime and passed as multi-modal inputs to LLMs. This extends existing AI Trust Layer PII protection to file-based agent workflows, ensuring that sensitive content in documents and images is masked before it reaches the model.

No additional configuration is required. Existing AI Trust Layer policies with PII masking enabled for agents automatically apply to dynamically downloaded files. For details, refer to [PII masking](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/pii-masking).

**Correction, June 8, 2026**: This feature was released on June 5, 2026, but was not included in the release notes at the time.

### Containerized Relay client

You can now run the Relay client as a container image using Podman or Kubernetes, in addition to the existing Linux and Windows installations. The containerized deployment supports high-availability configurations, custom CA certificates, and proxy routing. Containerized deployment requires Relay client `26.4.1` or later.

For details, see [Deploying the Relay client as a container](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/deploying-relay-client-container).

### Trial organization creation requires a business email

When signing up for a trial organization using a social sign-in option (Google or Microsoft), the system now displays an error if you authenticate with a personal email, rather than silently routing you to a Community account. A business email account is required to create a trial organization.

For details, see [Accessing the platform](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/accessing-the-platform).

### Unified outbound IP ranges — transition begins

UiPath is unifying outbound IP ranges across Automation Cloud services. The current service-specific outbound IP ranges for several services are being merged and updated into a single set of unified outbound IP ranges per regions (for example, United States, Europe, etc.). Once the transition is complete, one regional set of IP ranges covers all services — you no longer need to maintain separate ranges per service.

**What is changing**: The following services are transitioning to unified outbound IP ranges: Automation Cloud Portal, Test Cloud Portal, AI Trust Layer, Notification Service, Orchestrator, Test Manager, Apps, Automation Ops, and Integration Service.

**What is not changing**: Outbound IP ranges for Insights, IXP, and Automation Cloud Robots - Serverless are not affected and retain their existing, service-specific ranges. Domains and inbound IP ranges are not changing for any service.

**United Arab Emirates, Switzerland, and South Korea**: These regions were not part of the previous per-service IP model. Their outbound IP ranges appear only on the [Configuring the firewall for Automation Cloud](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/configuring-the-firewall-for-cloud) page. If your tenant is in one of these regions, there are no legacy IP ranges to maintain and no dual-allowlist period applies — only the unified IP ranges are needed.

#### Timeline

| Date | Event |
| --- | --- |
| June 16, 2026 | New unified outbound IP ranges published. The 3-month transition window begins. |
| September 16, 2026 | Gradual rollout of unified outbound IP ranges begins. Legacy service-specific IP ranges are progressively phased out. |

#### What you need to do

1. **Add the new unified IP ranges now.** The full list, organized by region, is on the [Configuring the firewall for Automation Cloud](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/configuring-the-firewall-for-cloud) page.
2. **Keep both sets allowlisted until September 16, 2026.** The current service-specific IP ranges remain on the [Legacy - Configuring the firewall for Automation Cloud](https://docs.uipath.com/automation-cloud/automation-cloud/latest/admin-guide/configuring-the-firewall-for-cloud-legacy) page and are still active during this window.
3. **After September 16, 2026**: Continue allowlisting both the legacy and unified IP ranges until a subsequent release note confirms the legacy IP ranges can be safely removed.

:::warning
If the new unified IP ranges are not added to your firewall before September 16, 2026, traffic from UiPath services to your systems may be blocked once the rollout begins.
:::
